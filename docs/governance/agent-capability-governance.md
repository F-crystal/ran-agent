# Agent Capability Governance

Status: CURRENT (2026-06-30)

## Three Layers

1. Skills are shared knowledge. Cross-tool skills live in `/Users/fengran/.agents/skills/<skill>`.
2. Hooks are executable lifecycle code. Keep them host-specific and record them in `/Users/fengran/.agents/hook-policy/`.
3. Plugins and MCP servers are capability entry points. Keep caches host-managed and record enabled entries in `/Users/fengran/.agents/plugin-inventory/`.

## Write Rules

- New cross-tool skill: create or edit `/Users/fengran/.agents/skills/<skill>/SKILL.md`, then symlink that one skill into tool roots.
- Project-only skill: keep it in the project `skills/<skill>/SKILL.md`.
- Do not edit `/Users/fengran/.codex/skills`, `/Users/fengran/.claude/skills`, or other tool skill roots directly except to add/remove symlinks.
- Do not symlink whole skill roots.
- Do not edit plugin cache directories by hand.
- Do not put credentials, cookies, API keys, session JSONL, SQLite state, logs, or local cache files in any governance inventory.

## New Projects

Every new project that adds `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.mcp.json`, `skills/`, `hooks/`, or plugin config must include a short Agent Capability Governance section:

```markdown
## Agent Capability Governance

- Cross-tool skills live in `/Users/fengran/.agents/skills`; project-only skills stay in this repo's `skills/`.
- Hooks, plugins, and MCP entries are executable capability surfaces; record new or changed entries in `/Users/fengran/.agents/hook-policy/` or `/Users/fengran/.agents/plugin-inventory/`.
- Do not edit tool-specific skill copies directly; use per-skill symlinks from the shared source.
```

In this repo, `AGENTS.md` is the canonical root rule file and `CLAUDE.md` is only a shim to it. Do not maintain duplicate root rule sets.

## Enforcement

- The `agent-capability-governance` skill is installed from `/Users/fengran/.agents/skills`.
- Codex runs `/Users/fengran/.codex/hooks/agent_governance_guard.py` on `UserPromptSubmit` and `PreToolUse`: prompt events only remind; `PreToolUse` blocks direct writes into tool-specific shared skill roots.
- Claude runs `/Users/fengran/.claude/hooks/agent_governance_guard.py` on `UserPromptSubmit` and `PreToolUse` with the same behavior.
- Cursor runs `/Users/fengran/.cursor/hooks/agent_governance_guard.py` on `beforeSubmitPrompt` and `preToolUse` with the same behavior.
- Gemini, Reasonix, and tools without confirmed blocking hook semantics rely on their global/project instructions until a host-specific hook is verified.
- A macOS LaunchAgent runs `/Users/fengran/.agents/bin/agent_project_governance_watch.py --once` periodically to patch future project `AGENTS.md`/`CLAUDE.md`/`GEMINI.md` files that are missing this section.
- Inventory files use generated blocks; keep manual audit notes outside those blocks.
